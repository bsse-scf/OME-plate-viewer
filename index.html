About this viewer

What it does

A CQ3000 measurement is one XML file describing the plate and a folder of single-plane TIFFs — tens of thousands of them, hundreds of gigabytes. Nothing reads that directly.

This page reads the XML, works out where every field of view sits, and presents each well as a virtual OME-Zarr image: metadata generated on demand, chunks answered by slicing the TIFFs where they already are. A Service Worker serves those images over ordinary same-origin HTTP, and Neuroglancer opens them like any other OME-Zarr. 

20251027T134435_10X/     the folder you drop
├─ 00013515.ome.xml      what gets read
├─ Image/                stays exactly where it is
│  └─ W0001F0001T0001Z001C1.tif …
└─ 35_….wpp              plate geometry

Nothing is uploaded, nothing is converted and nothing is written. Close the tab and every trace of it is gone.

How the plate is put together

  • Fields into wells — the stage positions of a well's fields are clustered back onto their acquisition grid, and each field is cropped to the grid step so neighbours abut. One field is one chunk; nothing is blended and no pixel is resampled at full resolution.
  • Wells onto the plate — each virtual image carries a translation putting it at its real position on the plate, taken from the well pitch in the vendor's plate file. Opening several wells at once assembles them into one plate.
  • Coarser levels — every image also offers reduced resolutions, built by sampling rows and averaging columns, so a plate overview reads a fraction of the data instead of all of it.
  • Channels — colours, names and display ranges come from the acquisition's own metadata, so Neuroglancer opens one additive layer per channel with the right colour already set.

Using the viewer

Click a well on the plate map to open just that well, which loads immediately. Opening the whole plate is the same data at a coarser level — it streams in well by well and is worth the wait once.

Which browsers work

Chrome, Edge, Opera, Brave and other Chromium-based browsers.

Nothing is uploaded, so the page has to read the dropped folder where it already sits — which needs the File System Access API — and then serve it to Neuroglancer through a Service Worker. Firefox and Safari give a page only a private storage area of its own, never a folder on your disk, so there is nothing for this viewer to open there.
